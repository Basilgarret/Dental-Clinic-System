Backend and Front-End Integration

Dental Clinic System architecture overview

Frontend

  • Browser-based dashboard
  • Login, signup, appointments, patients
  • Role-based UI workflows

Backend

  • Express.js API server
  • Authentication and authorization
  • PostgreSQL data layer
The browser never talks directly to the database; it communicates through a backend API layer that validates requests and protects data.

System Architecture

  • Frontend: HTML, CSS, JavaScript modules in the Js folder
  • API server: Express app in Js/server.js
  • Routes: Business logic and endpoints in Js/routes/index.js
  • Database: PostgreSQL connection via Js/database.js
  • Sessions: Managed with express-session and PostgreSQL session storage
  • Security: CORS, rate limiting, password hashing, and role checks
Browser ↓ API Client (Js/api.js) ↓ Express API (Js/server.js) ↓ Routes + Middleware ↓ PostgreSQL Database

Front-End Integration Pattern

const API_BASE = window.location.port === '5500' ? `${window.location.protocol}//${window.location.hostname}:4000/api` : `${window.location.origin}/api`; async function apiRequest(path, options) { const res = await fetch(API_BASE + path, options); const data = await res.json(); if (!res.ok) throw new Error(data.error || 'Request failed'); return data; }
  • The front end centralizes requests through Js/api.js.
  • Every CRUD action uses the same wrapper, which reduces duplication and ensures consistent error handling.
  • Modules such as Auth.js, appointments.js, and clinic.js call the backend instead of directly manipulating the database.

Authentication and Session Flow

  • User submits username and password.
  • Auth.js sends POST /api/auth/login.
  • Backend validates input and checks the users table.
  • Server hashes and compares passwords with bcryptjs.
  • On success, a secure session is created and stored server-side.
  • Protected API requests rely on the user's session and role.

Session features

  • HTTP-only cookies
  • SameSite protection
  • Role checks with middleware
  • Automatic logout support

Example: Patient Appointment Request

  • Front end collects appointment details in a modal form.
  • Client calls apiPost('/appointments', values).
  • Backend validates the payload and inserts it into PostgreSQL.
  • Server returns the created appointment object.
  • UI updates the schedule without reloading the page.
await apiPost('/appointments', { patientId, dentistId, date, time, status: 'Pending' });

Backend Responsibilities

Validation

  • Required form fields
  • Role-specific rules
  • Duplicate username checks

Business Logic

  • Clinic registration flow
  • Appointment creation
  • Prescription and records updates

Database Access

  • Prepared SQL queries
  • Transaction handling
  • Notification generation

Security

  • CORS
  • Rate limiting
  • Session protection
  • Role authorization

Key Files Review

Js/server.js → Express app, middleware, static assets Js/api.js → shared HTTP wrapper for the frontend Js/routes/index.js → all API route logic and request handling Js/database.js → PostgreSQL pool configuration Js/Auth.js → login/auth UI behavior Js/index.html → main client shell and dashboards Js/appointments.js → appointment workflows and UI rendering

Why the Integration Works Well

  • Separation of concerns: UI and business logic are separated.
  • Consistency: All requests pass through the same API client.
  • Security: Authentication and authorization live in the backend.
  • Maintainability: Routes and database logic are organized into clear modules.
  • Scalability: New data features can be added without rewriting the client structure.

Conclusion

The Dental Clinic System demonstrates a strong frontend-backend integration model: the UI sends requests to a protected API, the backend enforces business rules and security, and the database provides persistent data storage. This architecture makes the application modular, secure, and easier to expand over time.
  • Frontend: user experience and dynamic rendering
  • Backend: validation, permissions, logic, sessions
  • Database: persistent storage and integrity
  • Result: a clean and maintainable clinic management platform
